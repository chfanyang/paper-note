# DELE-w0.5: Inferring Action from Future Latent State for Robotic Manipulation

- arXiv: 2608.22067
- 主题：World Action Model / Future-State Supervision / Flow Matching / Causal Mask

## 1. 核心问题

DELE-w0.5 认为，很多 WAM 通过生成一整段 future video 来学习世界动态，但机器人控制真正关心的往往不是每一帧的视觉细节，而是：

> 执行这一段动作以后，世界最终会变成什么状态？

因此它把传统的 dense future-video prediction 压缩成一个更紧凑的 endpoint future representation：

\[
(O_t, L) \rightarrow (A_t, O_{t+\Delta t})
\]

但需要特别注意：论文标题写的是 **“Inferring Action from Future Latent State”**，而按其 attention mask，action 在 forward 计算中实际上看不到 future latent。更准确的理解是：

\[
\boxed{O_t,L \rightarrow A_t \rightarrow O_{t+\Delta t}}
\]

即 future state 是训练时用来约束 action representation 的辅助监督，而不是推理时 action 的输入。

---

## 2. Future latent state 实际是什么

论文中的 future latent state 并不是显式的物理状态，也不是 object-centric state，而是未来观测经过 DINOv3 得到的视觉特征：

\[
z_{t+\Delta t}=\mathrm{DINOv3}(O_{t+\Delta t}).
\]

因此更准确的叫法其实是：

> **future DINO feature / future visual feature**

而不是严格意义上的 physical latent state。

它没有显式编码：

- object pose；
- contact state；
- drawer / articulated state；
- force；
- gripper-object relation；
- scene graph。

这也是当前机器人/world-model论文中“latent state”概念被泛化使用的一个典型例子。

---

## 3. 整体结构

模型分成两个 stream：

### Condition Stream

输入：

- Language instruction \(L\)
- Current observation \(O_t\)

流程：

```text
Language
  ↓ Text Encoder
  ↓ Projection

Current RGB
  ↓ Vision Encoder
  ↓ Projection

        concat
          ↓
Single-Stream Attention
          ↓
Condition tokens Z_c
```

Condition Stream 不加噪，所以 timestep 固定为：

\[
\tau_c=1.
\]

### Noise Stream

有两个预测对象：

1. action chunk \(A_t\)
2. future visual feature \(z_{t+\Delta t}\)

训练时分别加噪：

\[
A_t^\tau=\tau A_t+(1-\tau)\epsilon_a,
\]

\[
z_{t+\Delta t}^\tau
=\tau z_{t+\Delta t}+(1-\tau)\epsilon_f.
\]

之后 action token 和 future-state token 一起进入 Noise Stream，再与 Condition Stream 在顶层 masked attention 中交互。

---

## 4. Masked Attention 到底怎么实现

整个 joint attention 中可以把 token 分成四组：

\[
[L, O_t, A, F],
\]

其中 \(F\) 表示 future latent-state tokens。

理想的 block mask 为：

| Query \ Key | L | O_t | A | F |
|---|---:|---:|---:|---:|
| L | ✓ | ✓ | ✗ | ✗ |
| O_t | ✓ | ✓ | ✗ | ✗ |
| A | ✓ | ✓ | ✓ | **✗** |
| F | ✓ | ✓ | ✓ | ✓ |

即：

\[
\boxed{A\not\leftarrow F}
\]

但：

\[
\boxed{F\leftarrow A}.
\]

从 attention score 实现上，就是对：

\[
\frac{QK^\top}{\sqrt d}
\]

加一个 block mask：

- 允许 attend 的位置加 0；
- 禁止 attend 的位置加 \(-\infty\)；
- 再做 softmax。

因此 forward 信息流是：

\[
\boxed{(L,O_t)\rightarrow A\rightarrow F}.
\]

---

## 5. 为什么 future loss 还能影响 action

虽然 action 在 forward 里看不到 future，但是 future token 可以读取 action token：

```text
Action representation
      ↓
Future query attends action
      ↓
Future prediction loss
```

因此反向传播时：

```text
Future-state loss
      ↓ gradient
Future branch
      ↓
Action representation
```

所以 future-state supervision 的作用是：

> 强迫 action representation 包含足以解释未来状态变化的信息。

这和 GigaWorld-Policy 中的 action-centered causal WAM 很接近，本质是 **effect-supervised action representation learning**。

---

## 6. 推理时怎么把 future 去掉

训练时 token 序列是：

\[
[L,O_t,A^\tau,F^\tau].
\]

推理时直接删掉 future token group：

\[
\boxed{[L,O_t,A^\tau]}.
\]

也就是说：

- 不输入 future image；
- 不跑 future Vision Encoder；
- 不构造 future latent；
- 不做 future-state denoising；
- 不输出 future-state prediction。

推理流程：

```text
Current RGB + Language
        ↓
Condition Stream
        ↓
Noisy Action
        ↓
Noise Stream
        ↓
Masked Attention
        ↓
Action velocity
        ↓
更新 noisy action
        ↓
重复 flow-matching steps
        ↓
Action Chunk
```

因为训练时本来就有：

\[
A\not\leftarrow F,
\]

所以推理时删除 \(F\) 不会破坏 action 的 forward dependency。

---

## 7. 一个值得警惕的实现歧义：Noise Stream 是否可能提前泄漏 future

Figure 2 中，Noise Stream 内部先分别处理 action 和 future tokens，之后又有：

```text
Action tokens ─┐
               ├─ cat → Single-Stream Attention Block
Future tokens ─┘
```

如果这里的 `Single-Stream Attention Block` 是普通完全双向 self-attention，那么 action 在到达最上层 `Masked Attention Block` 之前，就可能已经读取了 future 信息：

\[
A\leftarrow F.
\]

这会破坏论文声称的 causal property。

因此要让论文逻辑成立，至少要满足以下之一：

1. Noise Stream 内部 cat 后的 attention 本身也使用同样的 block mask；
2. 图中画法只是简化，实际上 action/future 在顶层 masked attention 前并没有跨组交互。

论文图和正文在这一点上存在一定 implementation ambiguity。真正复现时需要看官方代码确认。

## 8. 和 GigaWorld-Policy 的关系

两者的信息流高度相似。

### GigaWorld-Policy

\[
\boxed{O\rightarrow A\rightarrow F_{video}}
\]

- action 看 current observation；
- action 不看 future video；
- future video 可以看 action；
- inference 删除 future video。

### DELE-w0.5

\[
\boxed{O\rightarrow A\rightarrow F_{DINO}}
\]

- action 看 current observation；
- action 不看 future DINO feature；
- future feature 可以看 action；
- inference 删除 future branch。

所以 DELE 更像：

> **把 Giga / Fast-WAM 式 training-only future supervision，从 dense future video 压缩成 endpoint DINO feature。**

真正的新意不是因果方向，而是 future representation 更 compact。

---

## 9. 和 LD4WAM 的区别

LD4WAM：

\[
\boxed{O\rightarrow F_{video}\rightarrow D\rightarrow A}
\]

- test-time 必须先生成 future video；
- dynamics queries 从 future 中提取 latent dynamics；
- action 读取 future + dynamics。

DELE：

\[
\boxed{O\rightarrow A\rightarrow F_{latent}}
\]

- action 不读取 future；
- future 只是训练监督；
- test-time 删除 future branch。

因此两者虽然都强调 “future latent / future dynamics”，实际 philosophy 完全不同：

- LD4WAM：future 是推理中间变量；
- DELE：future 是训练期 teacher / regularizer。

---

## 10. 为什么只预测 endpoint state 有道理

传统 future-video WAM 需要建模：

- intermediate appearance；
- lighting；
- texture；
- camera motion；
- robot appearance；
- 每一帧细节。

而 manipulation 中很多时候真正关心：

```text
冰箱关闭 → 冰箱打开
杯子在桌上 → 杯子在目标区域
Pepsi 在冰箱里 → Pepsi 被取出
```

所以用 endpoint feature 作为 auxiliary future supervision，可以减少不必要的视频生成负担。

这点是 DELE 最有价值的动机之一。

---

## 11. 但 endpoint state 不是 action 的唯一决定因素

同一个 final state 可能由很多轨迹实现：

```text
从左边抓
从右边抓
绕障碍过去
双臂交接过去
```

所以：

\[
F_{final}\not\Rightarrow A\text{ 唯一}.
\]

同样，在：

- insertion；
- pouring；
- contact-rich manipulation；
- obstacle avoidance；

中，中间过程可能比 final image 更关键。

因此 endpoint future 更适合被理解成：

> **goal/effect constraint**

而不是完整 action representation。

---

## 12. 实验与效率

论文主要在 Astribot S1 双臂真实机器人上评估，包括：

- 开门；
- 从冰箱取 Pepsi；
- 加冰；
- 把爆米花放入微波炉并启动。

使用长 action chunk（约 60 steps，双臂 14D action）。

论文报告 DELE 在 long-horizon 任务上的平均 task progress 和 full-task success 明显高于 \(\pi_{0.5}\)。

推理时 future branch 被完全移除，因此无需 test-time future-video generation，核心推理延迟约为十几 Hz 级别。

---

## 13. 对 “latent state” 这个术语的看法

论文把：

\[
\mathrm{DINOv3}(O_{t+\Delta t})
\]

称作 future latent state。

数学上它确实是一个 latent representation，但更严谨的叫法是：

> **future visual embedding / future visual feature**

因为它没有被专门学习成一个 dynamics-closed 或 structured world state。

一个更严格的术语层级可以是：

| 实际表示 | 更准确的名称 |
|---|---|
| Transformer 中间输出 | hidden feature |
| DINO / CLIP 输出 | visual feature / embedding |
| VAE 编码 | latent |
| 专门通过 bottleneck 学出的变量 | learned latent |
| 用于 dynamics rollout 的状态 | latent state |
| 描述状态变化的 bottleneck | latent dynamics |
| 有显式物理量结构 | physical / structured state |

因此读 DELE 时，建议直接把 `future latent state` mentally 翻译成：

\[
\boxed{\text{future DINO feature}}
\]

避免被 “state” 这个词过度影响。

---

## 14. 最终判断

DELE-w0.5 的标题会让人以为：

\[
Future\ State\rightarrow Action.
\]

但按其 attention mask，真正 forward dependency 是：

\[
\boxed{Current\ Context\rightarrow Action\rightarrow Future\ Feature}.
\]

future branch 的主要作用是通过 future-state prediction loss 对 action representation 施加 effect supervision；推理时 future branch 被完全删除。

因此更准确的定位是：

> **Future-State-Supervised Action Model**

而不是严格意义上的 “Inferring Action from Future State”。

它真正有价值的贡献，是把传统 WAM 中昂贵的 dense future-video supervision 压缩成一个更轻量的 endpoint future visual feature，从而保留 world-effect regularization，同时避免 test-time imagination。

### 与近期几篇 WAM 的简单对比

```text
Giga:
O → A → Future Video

DELE:
O → A → Future DINO Feature

LD4WAM:
O → Future Video → Latent Dynamics → A

DreamWAM:
重点研究 Future 应该由 RGB / Motion / Geometry / Semantics 中哪些表示组成
```

DELE 因而可以看成：

> **“少预测一点未来，但仍然让未来结果反向塑造 policy”** 的 WAM 路线。
