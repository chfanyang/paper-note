# TurboVLA: Real-Time Vision-Language-Action Model at 32 Hz on an RTX 4090 with <1 GB VRAM

- ArXiv: https://arxiv.org/pdf/2607.27205v1
- 方法名：TurboVLA
- 关键词：lightweight VLA、language-conditioned policy、cross-attention、ACT、real-time control

## 一句话概括

TurboVLA 将常见的 LLM-centric VLA：

```text
Vision → Large Language Model → Action
```

改成：

```text
Dense Vision + Lightweight Language → Action
```

具体结构是：

```text
DINOv3 dense visual tokens
+
BERT instruction tokens
→ 双向 vision-language cross-attention
→ ACT-style action decoder
→ 连续 action chunk
```

作者的目标不是做复杂高层 reasoning，而是在 execution-level manipulation 中移除高频控制回路里的大语言模型，以获得更低延迟和显存占用。

## 核心动机

许多 VLA 即使使用并行动作解码、action expert 或 flow matching，视觉和语言仍需先通过数十亿参数的 VLM/LLM。

作者认为，对于已经明确指定的低层操作指令，例如：

- 把三个碗堆起来；
- 按下订书机；
- 拿起滚筒；
- 移开扑克牌；

策略主要需要解决：

- 指令指的是哪个物体；
- 目标在当前图像中的位置；
- 需要执行哪种已知操作技能；
- 当前机器人状态下如何产生动作。

这类任务通常不需要：

- 开放式语言生成；
- 长篇推理；
- 自主任务分解；
- 复杂常识推断。

## 模型结构

### 1. 视觉编码

多相机图像分别经过 DINOv3，保留 dense patch tokens：

```math
Z_n^{v,(i)}=P_v(f_{img}(I_n^{(i)}))+E_{pos}^{(i)}+e_{view}^{(i)}
```

其中：

- `E_pos`：patch 位置编码；
- `e_view`：相机视角 embedding。

所有视角的 token 拼接后形成 `Z_n^v`。

这部分与 Patch Policy 的动机相似：精细操作需要保留 dense spatial features，而不是过早池化成一个全局向量。

### 2. 语言编码

指令送入 BERT，并保留整段 token sequence：

```math
Z^l=P_l(f_{text}(x))
```

不是只使用 CLS 或平均池化，因此动作词、物体词、数量和关系词都可以分别参与视觉 grounding。

### 3. Robot State

当前 proprioception 单独编码：

```math
Z_n^s=f_{state}(s_n)
```

它不进入前面的视觉—语言交互，而在 action decoder 阶段加入。

作者的分工是：

```text
视觉—语言模块：任务对应画面里的什么
Robot state：当前构型下如何执行
```

### 4. 双向 Vision-Language Interaction

每层包含两个方向的 cross-attention。

#### Language queries visual

语言 token 查询视觉 token，使语言表示知道指令中的对象在当前画面中位于哪里。

#### Visual queries language

视觉 token 查询语言 token，使视觉表示突出当前任务相关区域并弱化无关背景。

经过若干层后：

```math
Z_n^{vl}=[V_n^N;L_n^N]
```

此时视觉 feature 已被 instruction 条件化，语言 feature 也获得当前场景 grounding。

### 5. ACT-style Action Decoder

准备 `H` 个 learnable action queries：

```math
Q_a=[q_1,\ldots,q_H]
```

Action decoder 读取：

- `Z_n^{vl}`；
- robot state `Z_n^s`。

一次 forward 并行生成完整动作块：

```math
\hat A_n=D_\theta(Q_a,[Z_n^{vl};Z_n^s])
```

它没有：

- action token 自回归生成；
- diffusion 多步去噪；
- flow ODE integration；
- 语言 CoT 生成。

## 训练

使用标准 behavior cloning：

```math
\mathcal L=\|\hat A_n-A_n^*\|_1
```

没有额外 reasoning、caption 或 language-generation loss。

## 推理

一次控制更新：

```text
最新多相机图像
+ 固定语言指令
+ 当前 robot state
→ DINOv3 + BERT
→ 双向 V-L interaction
→ ACT decoder
→ action chunk
```

因为只需一次前向传播，所以能够达到较高控制频率。

## 实验结果

### LIBERO

作者报告：

- 参数量约 0.2B；
- 推理显存约 0.9 GB；
- 延迟约 31.2 ms；
- 平均成功率 97.7%。

### RoboTwin 2.0

- 约 0.4B 参数；
- 延迟约 43.4 ms；
- 平均成功率 60.2%。

### 真实机器人

在 Grab Roller、Move Playing Card、Press Stapler、Stack Bowls 四个任务上取得较高成功率。

## 关键消融

### 去掉语言

平均成功率明显下降，尤其 LIBERO-Goal 几乎失效，说明同一视觉场景对应多个任务时，仍然需要目标条件。

### Task ID 替代语言

Task ID 也能达到较高成功率，说明一部分 benchmark 中语言主要承担有限任务集合的索引作用。

### Cross-attention

简单拼接、单向交互和双向交互逐步提升，说明 instruction-conditioned visual grounding 是有效的。

## 与早期工作的关系

从结构上看，TurboVLA 很接近 2021–2024 年的 language-conditioned visuomotor policy：

```text
预训练视觉编码器
+ 轻量文本编码器
+ cross-attention
+ action decoder
```

类似思路在 CLIPort、BC-Z、HULC、PerAct、VIMA 等工作中已经出现。尤其 VIMA 已使用预训练文本编码器和 cross-attention 条件化控制器。

因此：

> `V + L → A` 并不是一个新的 VLA 范式，而是传统 language-conditioned robot policy 在当前 LLM-centric VLA 背景下的重新包装。

## 我和用户的最终看法

### 1. 架构创新偏弱

TurboVLA 的主要组件都不是新的：

- DINOv3 dense features；
- BERT language encoder；
- 双向 cross-attention；
- ACT-style decoder。

它没有提出新的：

- action representation；
- 训练目标；
- world model；
- test-time reasoning；
- 控制理论；
- 长时规划机制。

因此不应将其描述成全新的 VLA 建模范式。

### 2. 与大型 VLM-VLA 的轻量化比较存在能力错位

大型 VLM-VLA 通常还试图提供：

- 开放词汇理解；
- 未见对象和属性泛化；
- 组合语言理解；
- 高层任务分解；
- world knowledge；
- 长时 reasoning；
- 跨场景和跨 embodiment 泛化。

TurboVLA 主动假设指令已经是明确的 execution-level command，只负责低层执行。

随后在主要不需要上述能力的 LIBERO 和固定真实任务上比较参数、显存和速度，轻量模型更快是预期结果。

因此论文证明的是：

> 对封闭、明确、执行级的操作任务，没有必要让大型 VLM 运行在高频控制回路中。

它没有证明：

> TurboVLA 与大型 VLM-VLA 具备相同 generality，只是更轻量。

### 3. 简单任务确实不需要复杂模型

Task-ID baseline 已能接近语言模型表现，反而说明 LIBERO 中部分语言主要是任务索引，而不是复杂语义推理。

真正体现 VLM 价值的测试应包括：

- 未见物体类别；
- 新属性组合；
- 大量 paraphrase；
- 否定和关系推理；
- 开放词汇指令；
- 多阶段任务；
- 需要常识判断的工具使用；
- zero-shot 新任务。

论文没有充分覆盖这些场景。

### 4. 真正价值主要是工程价值

TurboVLA 有意义的部分是：

- 证明轻量 policy 可以在 30 Hz 左右执行语言条件操作；
- 显存和部署成本低；
- 将大型模型移出高频控制回路；
- 为“慢速高层 planner + 快速低层 executor”提供工程证据。

更合理的系统定位是：

```text
高层 LLM / VLM planner
→ 生成具体原子指令
→ TurboVLA 高频执行
```

### 5. 更准确的论文定位

相比“新的 VLA 范式”，更准确的描述是：

> 在当前 LLM-centric VLA 流行的背景下，重新验证轻量 language-conditioned visuomotor policy 在 execution-level manipulation 中仍然具有很强的性能—效率优势。

如果重新命名，它更像：

> Revisiting Lightweight Language-Conditioned Policies for Real-Time Robot Execution

## 最终结论

> TurboVLA 更像一篇以当前 VLA 叙事重新包装的轻量 language-conditioned visuomotor policy。结构创新有限，和大型 VLM-VLA 的效率比较也不是同等能力下的压缩。它真正有价值的是工程结果，以及对“高频控制是否必须经过大型 VLM”这一默认假设的反思。
